## Theory

### Interface Basics

**Physical vs Netdev:**
- **phy#0:** Physical radio — e.g., `phy#0` with 2.4/5 GHz, channels, HT/VHT/HE, etc. — one phy can have multiple netdevs (wlan0, wlan0-1)
- **netdev:** Network device — e.g., `wlan0` (managed), `wlan0mon` (monitor), `wlp0s20f3` (Predictable Network Interface Names)
- **Driver:** Kernel driver for chipset — e.g., `ath9k` (Atheros AR9271), `rt2800usb` (Ralink RT3070), `mt76x2u` (MediaTek MT7612U), `rtl88xxau` (Realtek RTL8812AU), `iwlwifi` (Intel)

**Naming:**
- Old: `wlan0`, `wlan1` — predictable but may change order
- New: `wlp0s20f3` — predictable based on bus, slot, function — `wlp0s20f3` = wireless, PCI bus 0, slot 20, function 3
- Monitor: `wlan0mon` or `wlan0` with type monitor — airodump-ng creates `wlan0mon`

### iw vs iwconfig vs ip

**iw (modern, nl80211, recommended):**
- Uses nl80211 netlink interface, modern, supports all new features (HT/VHT/HE, monitor, AP, mesh, P2P, regulatory, etc.)
- Commands: `iw dev`, `iw phy`, `iw reg`, `iw dev wlan0 scan`, `iw dev wlan0 set type monitor`, `iw dev wlan0 connect`, etc.
- **Use this — iwconfig is deprecated**

**iwconfig (legacy, WEXT, deprecated):**
- Uses Wireless Extensions (WEXT), old, doesn't support HT/VHT/HE, monitor mode limited, not recommended
- Commands: `iwconfig wlan0`, `iwconfig wlan0 mode monitor`, `iwconfig wlan0 essid LAB-WIFI`, etc.
- **Don't use — use iw**

**ip (modern, for link):**
- Uses netlink, for link up/down, IP, etc.
- Commands: `ip link set wlan0 up`, `ip link set wlan0 down`, `ip addr add`, `ip link show`
- Use with iw — iw for wireless, ip for link

**For PT:** Use `iw` for wireless, `ip` for link, `rfkill` for block, `iw reg` for regulatory. Don't use `iwconfig`.

### USB Adapters & Chipsets

**Built-in (Intel iwlwifi):**
- Intel AX200, AX210, etc. — 2.4/5/6 GHz, HT/VHT/HE, but monitor mode limited, injection often not supported, driver iwlwifi, good for managed, not ideal for PT
- Check: `lspci -k | grep -A 3 Network`, `iw phy` shows capabilities, but injection test fails

**USB Adapters (for PT, need monitor + injection):**
- **Atheros AR9271 (ath9k):** 2.4 GHz only, HT20, monitor + injection excellent, driver ath9k, plug-and-play, no firmware needed, best for 2.4 GHz, e.g., ALFA AWUS036NHA, TP-Link TL-WN722N v1 (v2/v3 use different chipset)
- **Ralink RT3070 (rt2800usb):** 2.4 GHz, HT20, monitor + injection good, driver rt2800usb, e.g., ALFA AWUS036NH
- **Ralink RT3572 (rt2800usb):** 2.4/5 GHz, HT20/HT40, monitor + injection good, e.g., ALFA AWUS036NHA dual band?
- **MediaTek MT7612U (mt76x2u):** 2.4/5 GHz, HT/VHT, monitor + injection good, driver mt76x2u, e.g., ALFA AWUS036ACM, AWUS036ACHM (MT7612U + MT7603U), good for 5 GHz, recommended for dual band
- **Realtek RTL8812AU (rtl88xxau):** 2.4/5 GHz, HT/VHT, monitor + injection with custom driver (aircrack-ng rtl8812au), e.g., ALFA AWUS036ACH, AWUS036ACHM (some use RTL8812AU), needs driver install, not plug-and-play, but good for 5 GHz
- **Realtek RTL8814AU (rtl8814au):** 2.4/5 GHz, HT/VHT, 4 streams, monitor + injection with custom driver, e.g., ALFA AWUS036ACHM? Actually AWUS036ACHM uses MT7612U, AWUS1900 uses RTL8814AU

**Recommended for this academy (zero-cost simulated first, hardware later):**
- Start with built-in Intel for managed mode, simulated labs via PCAPs (zero-cost)
- Later, buy ALFA AWUS036ACHM (MT7612U, dual band 2.4/5 GHz, monitor + injection, plug-and-play with mt76x2u, ~$40) or AWUS036NHA (AR9271, 2.4 GHz only, ~$30) for hardware labs
- Don't buy expensive adapter initially — use simulated labs first, as per requirement.md zero-cost philosophy

### Driver & Firmware

**Driver:** Kernel module for chipset — e.g., `ath9k`, `rt2800usb`, `mt76x2u`, `rtl88xxau`, `iwlwifi`

**Firmware:** Binary blob for chipset — e.g., `ar9271.fw`, `rt2870.bin`, `mt7662u.bin`, `rtl8812au_fw.bin`, usually in `/lib/firmware/`

**Check driver:**
```bash
lspci -k | grep -A 3 Network
# Shows: Network controller: Intel Wi-Fi 6 AX200, Subsystem, Kernel driver in use: iwlwifi, Kernel modules: iwlwifi

lsmod | grep ath9k
# Shows: ath9k, ath9k_common, ath9k_hw, ath, mac80211, cfg80211

dmesg | grep firmware
# Shows: firmware loaded, etc.
```

**For PT:** If driver doesn't support monitor/injection, need custom driver (e.g., rtl8812au from aircrack-ng repo). For AR9271 and MT7612U, mainline driver supports monitor/injection, plug-and-play.

### rfkill & NetworkManager

**rfkill:** Blocks wireless — soft block (software) and hard block (hardware switch)

```bash
rfkill list
# Shows: 0: phy0: Wireless LAN, Soft blocked yes, Hard blocked no

rfkill unblock wifi
rfkill unblock all
```

**NetworkManager:** Manages wireless connections, may interfere with monitor mode — need to stop or set unmanaged

```bash
systemctl stop NetworkManager
# or
nmcli dev set wlan0 managed no
```

**For PT:** Before monitor mode, unblock rfkill, stop NetworkManager or set unmanaged, otherwise NetworkManager will try to manage interface and interfere.

### Regulatory Domain

**Regdom:** Country code determines allowed channels, power, DFS, 6 GHz

```bash
iw reg get
# Shows: country US, etc.

iw reg set US
# Sets US regdom, allows Ch1-11 2.4 GHz, Ch36-165 5 GHz, Ch1-233 6 GHz with AFC

iw reg set DE
# Sets Germany, Ch1-13 2.4 GHz, Ch36-140 5 GHz, Ch1-233 6 GHz low power
```

**For PT:** Set regdom to US or BO (Bolivia, allows all channels) for scanning all channels, but respect local regulations — don't use high power illegally.

Answer: `ip link set wlan0 down`, `iw dev wlan0 set type monitor`, `ip link set wlan0 up`, `iw dev` shows type monitor, channel 6, then `aireplay-ng --test wlan0` injection test. Also `rfkill unblock wifi`, `systemctl stop NetworkManager` or `nmcli dev set wlan0 managed no` before. Evidence: Interface type monitor, channel, injection test success.
