# Managed vs Monitor — Monitor Mode & Injection

## Learning Objectives
- Understand interface modes: managed, monitor, AP, mesh, IBSS, P2P
- Learn monitor mode: what it is, why needed, how to enable, what it captures
- Understand packet injection: what it is, why needed, how to test, legal/ROE
- Learn why monitor/injection requires hardware — can't simulate RF perfectly
- Understand simulated vs hardware labs — zero-cost vs RF adapter

## Theory

### Interface Modes

**Managed (Client, STA):**
- Normal mode — client connects to AP, associates, gets IP, sends data
- Only captures frames for its BSSID and broadcast, not all RF
- Can't capture other BSSIDs, can't capture probe requests from other clients (except broadcast), can't capture EAPOL for other clients (unless in same BSS and connected)
- **Use:** Normal Wi-Fi usage, wpa_supplicant, NetworkManager
- **Commands:** `iw dev wlan0 set type managed`, `iw dev wlan0 connect LAB-WIFI`, `wpa_supplicant -i wlan0 -c wpa_supplicant.conf`

**Monitor (RFMON):**
- RF monitor mode — captures all 802.11 frames in range on current channel, regardless of BSSID, regardless of association, passive (no tx except injection)
- Captures beacons, probe req/resp, auth, assoc, deauth, disassoc, data, EAPOL, etc. for all BSSIDs on channel
- No IP, no association, just raw 802.11 frames — need Wireshark, airodump-ng, Kismet, Scapy to analyze
- **Use:** Wireless recon, packet capture, handshake capture, deauth detection, rogue detection — core for wireless PT
- **Commands:** `ip link set wlan0 down`, `iw dev wlan0 set type monitor`, `ip link set wlan0 up`, `iw dev wlan0 set channel 6`, `airodump-ng wlan0`, `wireshark -i wlan0`, `tshark -i wlan0`
- **Requires:** Hardware with monitor mode support — AR9271, MT7612U, RTL8812AU, etc. — built-in Intel often limited

**AP (Access Point, Master):**
- AP mode — creates AP, beacons, handles auth/assoc, EAPOL, data — hostapd
- **Use:** Rogue AP lab, Evil Twin lab, captive portal lab — hostapd with SSID, BSSID, channel, security, etc.
- **Commands:** `hostapd hostapd.conf`, `hostapd.conf` with `interface=wlan0`, `ssid=LAB-WIFI`, `hw_mode=g`, `channel=6`, `wpa=2`, `wpa_key_mgmt=WPA-PSK`, `rsn_pairwise=CCMP`, `wpa_passphrase=...`, `wps_state=0`, `ieee80211w=2`, etc.
- **Requires:** Hardware with AP mode support — most USB adapters support AP mode, built-in Intel may support

**Mesh Point (802.11s):**
- Mesh mode — 802.11s mesh networking, multiple APs form mesh, no central controller
- **Use:** Mesh testing, not common in enterprise, but possible
- **Commands:** `iw dev wlan0 set type mp`, `iw dev wlan0 mesh join`

**IBSS (Ad-hoc):**
- Independent BSS — ad-hoc network, no AP, clients directly communicate
- **Use:** Ad-hoc testing, rare now, but possible
- **Commands:** `iw dev wlan0 set type ibss`, `iw dev wlan0 ibss join`

**P2P (Wi-Fi Direct):**
- P2P-client, P2P-GO (Group Owner) — Wi-Fi Direct, device-to-device without AP
- **Use:** Wi-Fi Direct testing, e.g., printers, TVs
- **Commands:** `iw dev wlan0 set type __p2pcl`, `wpa_supplicant` with P2P

**For PT:** Managed for normal usage, Monitor for recon/capture, AP for rogue lab. This academy: Simulated labs use PCAPs (no hardware), hardware labs use monitor/AP modes with USB adapter.

### Monitor Mode Deep Dive

**What monitor mode does:**
- Puts radio in RF monitor mode — receives all 802.11 frames on current channel, regardless of BSSID, regardless of association, regardless of encryption (captures encrypted data frames too, but can't decrypt without PTK)
- No filtering by BSSID — captures all
- No IP stack — raw 802.11 frames, need to set channel manually (`iw dev wlan0 set channel 6`), or channel hopping (airodump-ng hops channels 1-13, 36-165)
- Captures management (beacon, probe, auth, assoc, deauth, disassoc), control (RTS/CTS/ACK), data (QoS Data, EAPOL)

**Why monitor mode needed:**
- **Recon:** Discover APs, SSIDs, BSSIDs, channels, security, clients, hidden SSIDs, PNL — need to capture beacons and probe requests for all BSSIDs, not just connected
- **Handshake capture:** Capture EAPOL M1-M4 for WPA2-PSK offline audit (authorized only) — need to capture EAPOL for target BSSID and client, which requires monitor mode on target channel
- **PMKID capture:** Capture EAPOL M1 with PMKID — clientless, single frame, but need monitor mode on target channel
- **Deauth detection:** Capture deauth frames — many deauth same BSSID short interval = likely attack, need monitor mode to capture deauth
- **Rogue detection:** Capture beacons for same SSID different BSSID not in authorized list — need monitor mode to capture all beacons
- **Client enumeration:** Capture probe requests with PNL — need monitor mode to capture probe requests from all clients

**Without monitor mode (managed):**
- Only captures frames for connected BSSID and broadcast — misses other APs, misses other clients, misses EAPOL for other clients (unless connected to same BSS)
- Can't do wireless recon properly — need monitor

**Enable monitor mode:**
```bash
# Check current
iw dev
# Shows: type managed

# Unblock rfkill, stop NetworkManager
rfkill unblock wifi
systemctl stop NetworkManager
# or nmcli dev set wlan0 managed no

# Down, set monitor, up, set channel
ip link set wlan0 down
iw dev wlan0 set type monitor
ip link set wlan0 up
iw dev wlan0 set channel 6
iw dev
# Shows: type monitor, channel 6 (2437 MHz), width 20 MHz

# Capture
airodump-ng wlan0
# Shows: BSSID, PWR, Beacons, #Data, CH, MB, ENC, CIPHER, AUTH, ESSID, STATION, etc.

# Wireshark
wireshark -i wlan0 &
# or tshark
tshark -i wlan0 -Y "wlan.fc.type_subtype==8" -T fields -e wlan.bssid -e wlan_mgt.ssid -e wlan_mgt.ds.current_channel
```

**Channel setting:**
- Monitor mode captures only current channel — need to set channel to target AP channel, or channel hopping
- `iw dev wlan0 set channel 6` sets Ch6 2437 MHz 20 MHz
- `iw dev wlan0 set channel 36` sets Ch36 5180 MHz 20 MHz
- `iw dev wlan0 set channel 6 HT40+` sets Ch6 40 MHz
- airodump-ng hops channels by default — scans all channels, but may miss frames if hopping fast
- For targeted capture (handshake), set fixed channel to target AP channel

**For PT:** Monitor mode is essential for hardware labs, but simulated labs in this academy use PCAPs — no hardware needed, zero-cost. When you have USB adapter, use monitor mode for real RF.

### Packet Injection

**What injection is:**
- Transmit arbitrary 802.11 frames — deauth, disassoc, auth, assoc, probe req, data, etc. — using raw sockets, via `aireplay-ng`, `Scapy`, `aireplay-ng --deauth`, `aireplay-ng --fakeauth`, etc.
- Requires driver support for injection — not all drivers support, need to test

**Why injection needed:**
- **Deauth:** `aireplay-ng --deauth 10 -a BSSID -c Client` — deauth client to force reconnect, capture handshake (lab only, prod deauth usually not allowed without ROE, DoS)
- **Fake auth:** `aireplay-ng --fakeauth 0 -a BSSID -h ClientMAC wlan0` — fake authentication to AP for WEP attacks (WEP PTW needs fake auth + ARP replay)
- **ARP replay:** `aireplay-ng --arpreplay -b BSSID -h ClientMAC wlan0` — ARP replay for WEP IV collection
- **Rogue AP:** Not injection, but AP mode — hostapd

**Injection test:**
```bash
# Monitor mode first
ip link set wlan0 down
iw dev wlan0 set type monitor
ip link set wlan0 up
iw dev wlan0 set channel 6

# Test injection
aireplay-ng --test wlan0
# Shows:
# 10:00:00  Trying broadcast probe requests...
# 10:00:02  Injection is working!
# 10:00:02  Found 1 AP
# Or:
# 10:00:00  Injection is not working, driver not supported
```

**For PT:** Injection needed for WEP attacks (fake auth + ARP replay), deauth (handshake capture facilitation), but deauth is DoS and usually not allowed in prod without explicit ROE — only lab. This academy: Simulated labs don't need injection — PCAPs already have deauth frames, handshake, etc. Hardware labs need injection for WEP and deauth (lab only).

**Legal/ROE:**
- Deauth is DoS — disconnects clients, disruption, may violate FCC (jamming is illegal, deauth is not jamming but still DoS), company policy, may be illegal without authorization
- Only use deauth in own lab with explicit ROE, never on public Wi-Fi, never on prod without written permission
- This academy: Deauth PCAPs self-generated via Scapy, simulated, safe, zero-cost, no RF transmission — for analysis, not for actual deauth in prod

### Why Hardware Needed — Can't Simulate RF Perfectly

**What can be simulated (zero-cost, no hardware, PCAPs/configs):**
- PCAP analysis — beacon, probe, auth, assoc, EAPOL, deauth, WPS, RSN, etc. — real Scapy-generated PCAPs, like in this academy — 16 PCAPs
- Config analysis — hostapd.conf, wpa_supplicant.conf, FreeRADIUS clients.conf, users — audit WPS, PMF, PSK strength, ca_cert, secret
- Traffic analysis — Wireshark filters, association flow, evidence collection, frame numbers
- Handshake analysis — ANonce, SNonce, MIC, PMKID, EAP type, identity
- Deauth analysis — count deauth, reason codes, PMF status
- Rogue analysis — same SSID different BSSID not in authorized list, client assoc to rogue
- Captive portal analysis — open, HTTP redirect, MAC bypass, isolation
- Enterprise analysis — 802.1X roles, EAP, RADIUS, cert validation
- Corporate attack chain — 3 SSIDs + rogue + deauth + segmentation + isolation
- Methodology, reporting, retest — evidence chain custody, professional reporting

**What requires hardware (real RF, monitor mode, injection, AP mode, physical):**
- Monitor mode on real radio — capture real RF, not just PCAP replay
- Packet injection — transmit real RF frames — deauth, fake auth, ARP replay
- Real RF propagation — signal strength, RSSI, distance, walls, multipath, fading
- Channel interference — 2.4 GHz 40 MHz overlap, real interference, DFS radar
- Actual AP beaconing — real AP with hostapd, real beacons, real clients
- Real client/AP association — real client connects to real AP, real handshake, real data
- Physical proximity — parking lot, lobby, adjacent building, range with antenna
- Real-world rogue AP behavior — real client may auto-connect to stronger rogue, real signal strength, real roaming

**Don't blur categories — this academy clearly distinguishes:**
- **SIMULATED:** No hardware, PCAPs, configs, logs — zero-cost, local-first, safe, for learning
- **HARDWARE:** Requires USB adapter with monitor+injection+AP mode, real RF, authorized lab only, for validation

**For PT:** Start with simulated (zero-cost, as per requirement.md), master methodology, evidence, reporting, then add hardware where genuinely required for RF behavior — don't buy hardware immediately, extract max from simulated first.

## VAPT Relevance

- **Recon:** Monitor mode needed for hardware recon, but simulated recon via PCAPs is zero-cost and teaches methodology
- **Evidence:** Monitor mode PCAP has same evidence as simulated PCAP — frame numbers, BSSID, channel, etc. — methodology same
- **ROE:** Deauth and rogue AP require explicit ROE, even in lab — don't do in prod without permission, don't do on public Wi-Fi
- **Safety:** Simulated labs safe, no RF tx, no disruption, no legal risk — start here

## Attack → Defense → Retest

- **Attack:** No monitor mode, can't capture handshake, can't detect deauth, can't detect rogue
- **Defense:** Use monitor mode with USB adapter AR9271/MT7612U, injection test success, capture beacons/probes/EAPOL, WIDS authorized list, PMF required
- **Retest:** Monitor mode works, injection works, capture all frames, deauth detection, rogue detection, handshake capture (lab only)

## Interactive Check

> You have built-in Intel AX200, `iw phy` shows monitor mode supported but `aireplay-ng --test wlan0` shows injection not working. What does it mean and what would you do?

Answer: Monitor mode may be supported for capture, but injection not supported by driver iwlwifi — can't transmit deauth, fake auth, ARP replay. For simulated labs, no injection needed — PCAPs already have deauth, handshake, etc. For hardware labs requiring injection (WEP PTW, deauth), need USB adapter with injection support — AR9271 ath9k or MT7612U mt76x2u, plug-and-play, injection working. Don't buy immediately — use simulated first, as per zero-cost philosophy. Evidence: `iw phy` capabilities, injection test result.
