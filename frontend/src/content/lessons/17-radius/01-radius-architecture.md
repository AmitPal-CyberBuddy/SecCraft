### RADIUS Basics — Ports 1812 Auth 1813 Accounting UDP Shared Secret MD5 Obfuscation Not Encryption Use RadSec TLS

**RADIUS Basics:**

- **Ports:** 1812 auth, 1813 accounting (old 1645/1646) — UDP — client AP/NAS → server — e.g., AP 192.168.1.1 NAS IP → RADIUS 192.168.1.10 port 1812 — Access-Request — RADIUS server validates credentials LDAP AD local users file — returns Access-Accept with MSK VLAN etc — or Access-Reject — accounting port 1813 — Accounting-Request Start Stop Interim-Update usage session time — for PT, RADIUS ports 1812 auth 1813 accounting — filter `radius.code==1` Access-Request, `==2` Access-Accept, `==3` Access-Reject, `==4` Accounting-Request, `==5` Accounting-Response — e.g., `radius` filter — RADIUS — Access-Request Accept Reject Accounting
- **Protocol:** UDP client AP/NAS → server shared secret for MD5 obfuscation of password not encryption for whole packet use RadSec TLS for encryption RFC 6614 — RADIUS protocol UDP — not TCP — no encryption for whole packet — only password obfuscation via MD5 secret + Request Authenticator — not strong — if attacker can sniff RADIUS traffic on same network e.g., port mirroring or compromised switch, can see username User-Name attribute cleartext, maybe password obfuscated but weak if secret weak brute-force — better use RadSec RADIUS over TLS for encryption — RFC 6614 — RadSec encrypts whole RADIUS packet via TLS — better than UDP with MD5 obfuscation — for PT, if RADIUS over UDP not RadSec, Low? Actually if network not isolated, Medium? Recommend RadSec TLS or IPsec or isolated management VLAN for RADIUS
- **Shared Secret:** Must be strong 22+ chars random not default testing123 secret password — shared secret used for MD5 hash of password obfuscation and for Message-Authenticator HMAC-MD5 — if weak testing123 secret short guessable, attacker who can sniff RADIUS traffic can brute-force secret — RADIUS password obfuscation uses MD5 secret + Request Authenticator — weak secret easier to brute-force — also if attacker can MitM RADIUS? Better use RadSec RADIUS over TLS or strong secret + isolated network — for PT, weak shared secret testing123 Medium finding — recommend strong 22+ chars random per NAS unique if possible not default testing123 secret password
- **AAA:** Authentication who are you Authorization what can you do VLAN ACL Accounting logs start/stop usage — AAA — Authentication who are you — e.g., username user@corp.com password StrongPass123 or client cert — Authorization what can you do VLAN ACL — e.g., RADIUS returns Tunnel-Private-Group-Id VLAN 100 Corp for user1 VLAN 200 Guest for guest — Authorization — VLAN assignment per user — ACL per user — Accounting logs start/stop usage session time data usage — for PT, AAA — Authentication Authorization Accounting — RADIUS does AAA — for PT, check AAA — logs — accounting — etc.
