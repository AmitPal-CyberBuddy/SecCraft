# Beacon, Probe, Auth, Assoc — Full Association Flow

## Learning Objectives
- Understand full association flow: Beacon → Probe Req/Resp → Auth → Assoc Req/Resp → EAPOL → Data
- Learn Information Elements (IE): SSID, Supported Rates, DS Parameter Set, TIM, RSN, HT/VHT/HE, WPS, Vendor
- Understand hidden SSID reveal via Probe Response and Assoc Request
- Learn reason codes and status codes
- Map flow to Wireshark filters and evidence collection

## Theory

### Full Flow

```
Time →
AP:    Beacon (100ms)  Beacon  Probe Resp (to client)  Auth Resp (seq2)  Assoc Resp (status0 AID1)  EAPOL M1 ANonce  EAPOL M3 ANonce+GTK  Data (encrypted)
        |               |       |                       |                 |                        |                |                    |
Client:                 Probe Req (LAB-WIFI PNL)        Auth Req (seq1)   Assoc Req (SSID+RSN)                      EAPOL M2 SNonce+MIC  EAPOL M4 ACK  Data

Frames:
1: Beacon SSID LAB-WIFI BSSID AA:BB:CC:DD:EE:FF Ch6 WPA2-PSK CCMP
3: Probe Request SA 11:22:33:44:55:66 SSID LAB-WIFI (PNL leak) DA FF:FF:FF:FF:FF:FF
10: Probe Response DA 11:22:33:44:55:66 SA AA:BB:CC:DD:EE:FF SSID HIDDEN-LAB (hidden reveal)
5: Auth Req SA 11:22:33:44:55:66 DA AA:BB:CC:DD:EE:FF algorithm 0 Open seq1
6: Auth Resp SA AA:BB:CC:DD:EE:FF DA 11:22:33:44:55:66 algorithm 0 seq2 status0 success
7: Assoc Req SA 11:22:33:44:55:66 DA AA:BB:CC:DD:EE:FF SSID LAB-WIFI RSN CCMP PSK HT capabilities
8: Assoc Resp SA AA:BB:CC:DD:EE:FF DA 11:22:33:44:55:66 status0 success AID1 RSN CCMP PSK
9: EAPOL M1 SA AA:BB:CC:DD:EE:FF DA 11:22:33:44:55:66 ANonce aabbccdd... Key ACK, no MIC
10: EAPOL M2 SA 11:22:33:44:55:66 DA AA:BB:CC:DD:EE:FF SNonce 11223344... MIC, RSN
11: EAPOL M3 SA AA:BB:CC:DD:EE:FF DA 11:22:33:44:55:66 ANonce, MIC, Install, GTK
12: EAPOL M4 SA 11:22:33:44:55:66 DA AA:BB:CC:DD:EE:FF MIC, ACK
13+: Data QoS Data SA 11:22:33:44:55:66 DA AA:BB:CC:DD:EE:FF BSSID AA:BB:CC:DD:EE:FF Protected (encrypted)
```

**State Machine:**
- State 1: Unauthenticated, Unassociated — client not auth, not assoc — can send probe, auth
- State 2: Authenticated, Unassociated — client auth success, not assoc — can send assoc
- State 3: Authenticated, Associated — client auth and assoc success, can send data and EAPOL

Deauth moves any state to State 1, Disassoc moves State 3 to State 2.

### Information Elements (IE) Deep Dive

IE format: 1 byte ID, 1 byte Length, Length bytes Data

**Common IEs:**
- **0 SSID:** 0-32 bytes, human name, empty length 0 for hidden beacon
- **1 Supported Rates:** 1-8 rates, 500 kbps units, e.g., 0x82 = 1 Mbps, 0x84 = 2 Mbps, 0x8B = 5.5 Mbps, 0x96 = 11 Mbps (0x80 bit indicates basic rate)
- **3 DS Parameter Set:** 1 byte, current channel, e.g., 6
- **5 TIM:** Traffic Indication Map, DTIM count, DTIM period, Bitmap Control, Partial Virtual Bitmap — AP tells clients in power save if data buffered
- **48 RSN:** RSN Version (1), Group Cipher Suite (00:0F:AC:04 CCMP), Pairwise Cipher Suite Count (1), Pairwise Cipher Suite List (00:0F:AC:04 CCMP), AKM Suite Count (1), AKM Suite List (00:0F:AC:02 PSK or 00:0F:AC:08 SAE or 00:0F:AC:01 EAP), RSN Capabilities (2 bytes, MFPC, MFPR, GTKS A, PTKSA Replay Counter), PMKID Count, PMKID List, Group Management Cipher Suite
  - **Group Cipher:** Broadcast/multicast encryption — CCMP (00:0F:AC:04) good, TKIP (00:0F:AC:02) legacy bad
  - **Pairwise Cipher:** Unicast encryption — CCMP good, TKIP bad
  - **AKM:** Authentication and Key Management — PSK (00:0F:AC:02) WPA2-Personal, SAE (00:0F:AC:08) WPA3-Personal, EAP (00:0F:AC:01) Enterprise, PSK+SAE (transition)
  - **MFPC/MFPR:** Management Frame Protection Capable/Required — MFPC=0 MFPR=0 PMF disabled, MFPC=1 MFPR=0 PMF capable optional, MFPC=1 MFPR=1 PMF required (WPA3 mandates required)
  - **For PT:** RSN IE is security — check ciphers (CCMP good, TKIP bad), AKM (PSK vs SAE vs EAP), PMF (disabled/capable/required), group cipher, pairwise cipher. Evidence: RSN IE from beacon frame.
- **45 HT Capabilities:** HT Capabilities Info (2 bytes), A-MPDU Parameters (1 byte), Supported MCS Set (16 bytes), HT Extended Capabilities (2 bytes), TX Beamforming Capabilities (4 bytes), ASEL Capabilities (1 byte) — 802.11n, 20/40 MHz, MCS, spatial streams
- **61 HT Operation:** Primary Channel, HT Operation Info, Basic MCS Set — 802.11n operation
- **191 VHT Capabilities:** VHT Capabilities Info (4 bytes), Supported VHT MCS and NSS Set (8 bytes) — 802.11ac, 80/160 MHz, 256-QAM, MU-MIMO
- **192 VHT Operation:** Channel Width, Channel Center Frequency Segment 0/1, Basic VHT MCS and NSS Set — 802.11ac operation
- **255 ext 35 HE Capabilities:** HE MAC Capabilities (6 bytes), HE PHY Capabilities (11 bytes), Supported MCS Set, etc. — 802.11ax, OFDMA, 1024-QAM, BSS coloring
- **255 ext 36 HE Operation:** HE Operation Parameters, BSS Color, Basic HE MCS and NSS Set, etc. — 802.11ax operation
- **221 Vendor Specific:** OUI + type + data — WPS OUI 00:50:F2:04, Microsoft OUI 00:50:F2:02 WMM, etc. — WPS IE is vendor specific with OUI 00:50:F2:04

**WPS IE:**
- ID 221, Length variable, OUI 00:50:F2:04, type, data — WPS Version, WPS State (1 unconfigured, 2 configured), AP Setup Locked, Selected Registrar, Device Password ID, Selected Registrar Config Methods, Response Type, UUID-E, Manufacturer, Model Name, Model Number, Serial Number, Primary Device Type, Device Name, Config Methods
- **For PT:** WPS IE in beacon/probe response indicates WPS enabled — High finding, 11k PIN flaw. Filter `wps` in Wireshark. Evidence: Frame number, BSSID, WPS IE OUI, WPS State.

**Hidden SSID:**
- Beacon SSID IE length 0, SSID empty — AP hides SSID, but not security — probe response and assoc request contain real SSID
- **Reveal methods:**
  - Probe Response: Client sends probe req for hidden SSID (directed probe), AP responds with probe resp containing real SSID — filter `wlan.fc.type_subtype==5` and check SSID
  - Assoc Request: Client assoc req contains real SSID even if beacon hidden — filter `wlan.fc.type_subtype==0` and check SSID
  - **For PT:** Hidden SSID not security, focus on WPA2/WPA3. Evidence: Hidden beacon frame 1 SSID empty length 0, Probe Response frame 10 SSID HIDDEN-LAB real, Assoc Request frame 7 SSID HIDDEN-LAB real.

### Reason Codes & Status Codes

**Reason Codes (Deauth/Disassoc):**
- 1 Unspecified
- 4 Disassociated due to inactivity
- 5 AP unable to handle all associated STAs
- 7 Class 3 frame received from nonassociated STA (common for deauth flood)
- 8 STA leaving BSS

**Status Codes (Assoc Resp):**
- 0 Successful
- 1 Unspecified failure
- 10 Cannot support all requested capabilities
- 12 Association denied due to reason outside scope of standard

**For PT:** Reason 7 with many deauth same BSSID short interval = likely deauth flood attack, not normal. Evidence: Deauth frames count, reason codes, BSSID, client MAC, PMF status.

## Attack → Defense → Retest

- **Attack:** Capture probe req PNL leak, use for targeted Evil Twin, capture handshake via deauth if PMF disabled

- **Retest:** Probe req random MAC wildcard SSID no PNL, beacon no WPS IE, PMF required deauth fails, handshake audit fails strong PSK
