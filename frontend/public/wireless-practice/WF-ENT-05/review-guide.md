# Public self-review guide

E1: EAP-TLS can avoid reusable network passwords where managed certificate lifecycle and supported clients exist; still validate server identity, client certificate mapping/key possession, issuance, renewal, revocation and device protection. E2: a broad CA without an expected server identity can accept an unintended same-root server. PEAP-MSCHAPv2 does not automatically expose its inner response to a passive observer; profile/runtime and tunnel evidence are required. E3: EAP-PWD is a password-authenticated EAP method, not a synonym for WPA3-Enterprise or SAE. Verify the applicable security profile and implementations. E4: a public certificate neither reveals its private key nor proves a live peer possessed it.

At 2026-10-01, both local policies accept server-good.pem. The ca-only policy also accepts server-wrong-name.pem; strict rejects it because its SAN is other.lab.example, not aaa.lab.example. Both reject the other-root issuer, expired certificate and client-only EKU. Trust, expected name, validity and purpose are distinct checks. These files are not a live certificate chain recovered from a PEAP capture, and the exercise does not test revocation, private-key possession, client overrides or actual EAP/TLS negotiation. “OpenSSL rejected” is not interchangeable with “my supplicant rejected”.

In radius.pcapng, pairs are frames 2→3 (ID 1), 4→5 (ID 2), 6→7 (ID 3) and 8→9 (accounting ID 5). Frame 10 uses a different source/secret and intentionally fails the documented secret's Message-Authenticator check. Frame 7's Access-Accept carries VLAN 100 and four-byte EAP-Success with no Type field. Neither validates AP placement or forwarding. These corrected outer AAA transactions retain illustrative direct method bytes, not a complete interoperable PEAP or EAP client/server session. No actual MSK/key transport is supplied.

For response Message-Authenticator, substitute the corresponding request authenticator and zero only the Message-Authenticator value; compute HMAC-MD5 under the lab secret. Then check the Response Authenticator over header fields, request authenticator, final attributes and secret. Accounting-Request is MD5 of header with zero authenticator plus attributes plus secret. Deterministic fixture nonces are not production randomness. Correlate identifier with endpoint/port, transaction context, outstanding request and clocks; IDs are only eight bits and can be reused.

S1: consistent only within the model's stated paths; not universal isolation. S2: secure client rejection, not evidence of wrong password or credential capture. S3: requested versus applied VLAN mismatch in the model; no application impact is measured. S4: insufficient placement/enforcement evidence; an Access-Accept and no response cannot certify segmentation. Never invent the missing AP/switch/client logs.

Review gates: source-cited reasoning; explicit actual file checks versus supplied-result review; CA and name separated; trust failure versus credential rejection distinguished; valid AAA integrity versus actual enforcement separated; methods versus Wi-Fi profiles distinguished; bounded future test plan; no live outcomes silently credited. Independent instructor and execution assessment remain separate from browser-local completion.
