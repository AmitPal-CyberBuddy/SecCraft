# Public review guide — consult after an attempt

This is a practice rubric, not a hidden answer key, automated grader or certification threshold. Use MET / REVISE / NOT ASSESSED with evidence for each criterion; do not average away an unsafe or unsupported claim.

| Criterion | Evidence required for MET |
| --- | --- |
| Scope and provenance | Names only the C-20 files, fictional source and offline permission; keeps Northwind and earlier scenes separate |
| Reproducibility | Current hash, file/frame/field and actual method; derived JSON not called independent corroboration |
| Inventory and prioritization | All three BSSIDs reconciled with partial owner list; uncertainty and intended CR-20 policy distinguished |
| Supported and non-finding conclusions | Same-BSSID advertisement comparison; CORP-A advertises planned AKM/PMF in supplied frames without implying overall security |
| Alternatives and limits | Unlisted same-name BSSID not labeled malicious; beacon not substituted for negotiated policy or client acceptance |
| Impact and retest | No invented business impact/severity; exact missing client/AP evidence, controls, authorization, stop and cleanup proposal |
| Professional handoff | Concise summary, action owner, limitations, protected evidence handling and explicit unresolved status |

Return for revision regardless of other criteria if the attempt authorizes real contact from packet addresses, calls this a production compromise, merges Northwind evidence, claims enforced PMF/SAE from beacons, treats a published fixture password as recovered client credentials, invents reviewer approval, or marks live remediation complete.

Reference-review.json is an illustrative bounded claim set, not exhaustive acceptable wording. A different supported interpretation with correct citations can be valid. A reviewer should ask: what evidence would falsify this claim? What observation would close it? Was that evidence actually supplied?

CORP-A's advertised 802.1X/MFPR matches the stated plan in the two supplied beacon frames. That narrow check yields no advertised-policy deviation; it does not audit its EAP method, certificate validation, authentication success or segmentation. Reporting no finding here is a legitimate result.

Independent review remains unavailable unless a real reviewer examines the submission. Record SELF-REVIEW if working alone.
