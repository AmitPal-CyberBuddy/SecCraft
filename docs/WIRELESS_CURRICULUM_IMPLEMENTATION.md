# Wireless curriculum: audit follow-up implementation

This records the follow-up to `WIRELESS_CURRICULUM_AUDIT.md`. The audit described the *previous* 27-lesson, 16-capture state. The available path now has **15 modules, 32 lessons, 18 deterministic synthetic captures, 15 five-question quizzes, 22 self-review challenges (66 tasks), 35 scenarios and 19 available labs** (three machine-answer-checked). The 52-hour path estimate is still indicative; the course does not verify field competence.

## Implemented and where to find it

1. **Beginner bridge:** `01-intro-wireless/00-network-and-tool-primer.md` explicitly teaches MAC versus IP, subnet and route reasoning, shell/tshark/Wireshark capture reading, hash/filter/frame provenance and the claim-versus-impact distinction. No adapter required. Module 01 lesson ordering includes it.
2. **Worked byte decoding:** `03-80211-architecture/02-worked-rsn-decode.md` traces RSN IE ID/length, little-endian counts, OUI/type selectors, PMF bits and a separate practice example before the existing transition-mode scenario. Module 03 now links it as a lesson.
3. **Safe RF readiness:** `04-kali-wireless-setup/02-owned-lab-readiness.md` gives an optional passive owned-hardware worksheet with scope, regulatory checks, troubleshooting, chain of custody, stop rules and an offline alternative. No fabricated RF result or injection task.
4. **Applied mechanisms:** module 07 includes a labelled toy WEP IV-keystream example and distinguishes configuration from key recovery; the merged Enterprise module includes an executable, checked RFC 2759 MS-CHAPv2 known-answer vector; module 15 includes a client/AP/AAA collection and negative-control matrix rather than pretending separate PCAPs are one EAP session. Modules 18/20 add an evidence-link challenge and independent peer-review gate, without awarding verified mastery.
5. **Corrected generated evidence:** `scripts/wififorge_labkit.py` used MFPR/MFPC masks `0x0010`/`0x0020` despite lessons correctly teaching IEEE RSN capabilities bits 6/7 (`0x0040`/`0x0080`). Fixed the masks and neighboring replay field definitions, regenerated all 16 earlier PCAPs, their offline JSON, SHA-256 inventory and manifest, and updated the authored handshake digest. `scripts/verify-lab-artifacts.py` now checks the literal correct masks and staged case policy bytes to prevent this regression. **Existing PCAP hashes changed; use the current manifest**, not old screenshots or external copies. Lesson identifiers and the three verified lab contracts remain unchanged.
6. **Independent staged capstone:** the generator creates `capstone/capstone-baseline.pcapng` and `capstone/capstone-retest.pcapng`, with reproducible lab PSK MICs, separate SHA-256 entries and bounded teaching notes in `capstone/CASE_NOTES.md`. Module 20's lesson, lab, quiz and `chal-15-engagement` now use this *new* Case C-20 rather than reusing module 19's methodology capture. The retest file checks **advertised** SAE/MFPR after a fictional change, not actual client negotiation. An unlisted same-SSID PSK BSS remains; ownership is unproven. The instructor guide was rewritten to stop misattributing generic fixtures to Northwind or claiming nonexistent log incidents, WEP exploitation and verified negative outcomes. Northwind ENG-01 remains planning only.
7. **Applied challenge coverage:** seven additional self-review challenges now cover modules 01, 03, 04, 07, 08, 18 and 20 with three evidence/limit/next-test tasks each, reducing the scenario-only gaps without representing local flags as verified mastery.
8. **Cross-file contract:** `verify-learning-data.mjs` checks 32 referenced lessons, all capture-backed available labs, and that final lab/challenge use the new case; the lab verifier checks case frame composition, per-BSSID advertised policy and baseline MIC against the published training candidate.

## Consolidated learning path (subsequent scope decision)

The learner now follows **15 modules / 32 lessons**: 09→08, 13→12, 16+17→15, and 19→20. The six Preview modules remain unchanged; Full has nine. The surviving IDs intentionally keep stable internal names even where numbering has gaps; visible sequence numbers are contiguous. The final lesson and module 20 quiz now test a technical offline case, not formal reporting. The old standalone reporting lesson is retired; optional ENG-01 remains a planning brief, not a required learning topic.

Browser-local persisted progress uses version 6: still-active lessons and labs/challenges follow their surviving parent, but old five-question quiz results for retired modules (and the changed module 20 quiz), plus the removed reporting lesson and replaced final-case lesson, are archived locally without new current credit or verified mastery. No instructor-graded or RF proficiency is inferred by migration.

## Not possible to mark complete from this repository

- No owned radio, client/AP fleet, RF authorization or regulatory approval was supplied, so **live injection, monitor-mode compatibility, WPS lockout, deauth effect, rogue ownership and client steering are NOT TESTED**. The new passive worksheet instructs a supervised test but does not claim its outcome.
- No real complete PEAP/EAP-TLS session with an effective managed-client profile, supplicant logs, certificate chain and linked AAA/switch policy exists here. The enterprise collection contract identifies how to obtain one; current EAP/RADIUS fixtures remain separate teaching examples.
- No live portal session/ACL enforcement test or independently observed full remediation exists. Case C-20's post-change bytes prove only a synthetic beacon advertisement. **No production retest passed.**
- No instructor performed learner-specific review. Existing quiz, XP and self-review flags remain local/unverified; the professional level is an instructional topic, **not professional qualification**. A genuine credential would require separately scoped real infrastructure, new client evidence, supervised practice, independent reviewers and trusted grading—outside this content-only task and not silently implemented as platform behavior.
